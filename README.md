# School Feeding Management — account and access module

This repository contains the account and access portion of the School Feeding Management System brief. The Laravel app is in [`app/`](app/). It implements shared sign-in with role routing, Field Staff account management, temporary passwords, manual WhatsApp handoff, password changes, recovery, session revocation, and protected reviewer accounts. Aceternity's Aurora background is used on account screens.

## Setup

Requirements: PHP 8.3+ with MySQL PDO, Composer, Bun, and MySQL with a UTF-8 (`utf8mb4`) database.

1. `cd app`
2. `composer install`
3. `bun install`
4. Copy `.env.example` to `.env` and run `php artisan key:generate`.
5. Set `APP_URL`, the MySQL connection values, `SFP_ADMIN_USERNAME`, and a strong `SFP_ADMIN_PASSWORD` in `.env`. Set `APP_DEBUG=false` outside local development.
6. Run `php artisan migrate --force` and `php artisan db:seed --force`.
7. Run `bun run build` and `php artisan serve` for local development. Serve `app/public` as the web root in production.

The initial Admin password expires after 48 hours and must be changed on first sign-in. Seeding is idempotent: rerunning it does not overwrite an existing Admin password. For Admin recovery, an operator with command access runs `php artisan sfp:reset-admin USERNAME`; the command displays a new 48-hour temporary password once.

For a reviewer site, set `SFP_DEMO_ENABLED=true` and all five `SFP_DEMO_*` variables in `.env` before seeding. Use distinct usernames and strong passwords. The demo Admin and Field Staff accounts retain their submitted credentials; their passwords and account status cannot be changed through the app. Share the working demo usernames and passwords with reviewers in the submission README or email. No live deployment or reviewer credentials are included in this repository.

## Roles and account behavior

- Admin reaches the dashboard and can create, search, edit, deactivate, reactivate, and reset Field Staff accounts. Admins cannot create other Admins in the app.
- Field Staff reaches a home page with Enter Delivery, My Entries, and Daily Delivery Report links. Delivery and reporting pages currently explain that those modules are pending.
- New or reset staff passwords are generated by the app, shown only in the immediate response, and sent manually through a prefilled WhatsApp link. They expire after 48 hours. No plaintext password is stored in the user table, session, or audit log.
- The creation form shows Field Staff and Active as fixed values. Before opening WhatsApp, Admin sees the exact recipient and fixed message. The app does not record or claim that the message was sent. Leaving the handoff page requires a reset to prepare another message.
- Correcting the username or WhatsApp number while an active account still has a temporary password invalidates that password and prepares a new handoff. Changing only the name does not rotate the password.
- Signed-in users can change their own password by providing the current one. A temporary password allows only its replacement and sign-out. Inactive accounts cannot sign in; deactivation and resets revoke existing sessions. Login attempts are throttled, and Remember me lasts up to 14 days.

## Packages

Laravel, React, Tailwind CSS, Aceternity Aurora Background, Vite, `clsx`, and `tailwind-merge`. The Aurora source was installed with the shadcn CLI. These are open-source packages; no paid service or WhatsApp API is used.

## Assumptions and limitations

- One shared sign-in page satisfies the brief's separate-login requirement through distinct accounts, role routing, and server-side permissions.
- Bangladesh time (`Asia/Dhaka`) is used for temporary-password expiry display. WhatsApp numbers are validated as Bangladesh mobile numbers and stored in international digit format.
- The selected WhatsApp handoff link contains the temporary password in its URL. Browser history or external logs may retain it. The link is shown once and the password expires after 48 hours.
